# Maintained migration-helper qualification

`helper-cases.json` supplies independent expected results for the maintained
qualification helpers. The existing migration and 91-case service packages
retain their exact bytes and meanings. These additional cases preserve all
native, source, coverage, resource, ownership and final acceptance requirements.

Record and text cases exercise bounded fixture preparation. Each invalid record
changes one field of the valid frozen base. Text construction admits at most
1,024 UTF-8 bytes and checks repetition and concatenation before growth. Scenario
guards reject malformed steps, unknown records, a closed writer and an occupied
selected absent endpoint. A valid direct SQL control retains exact typed readback
before the existing one-field constraint negatives. An occupied migrator baseline
must remain intact when concurrent migration qualification refuses to start.

Relay cases use actual Unix peers. No-frontend completion may report either a
receive timeout or a disconnected peer after the frontend worker expires; its
frontend result must be the selected two-second timeout. The separate Drop case
qualifies bounded worker joining and owned socket/directory absence. An owned
absent backend must report that connection failure and peer disconnection.
Closing the receiving direction exercises an actual forwarding write failure.
All cases retain actual errors, elapsed time, physical state and cleanup facts.

Service guards use the actual admitted service. Missing selection runs in an
isolated child. Whitespace changes affect an owned copy of the input. Temporary
synthetic-writer privilege changes must be restored and independently checked;
the guarded reset must deny before changing records. A declared-data mismatch
uses an owned protected copy with full static observation before live comparison.
A shortened copy of the lease must deny restart before any control publication
or native stop/start. Original selection, live identity and stored state remain
independently checked throughout these cases.

Control-file cases operate only in a separate owned directory. They qualify
bounded intake, the selected control kind/version/request hash, and deadlines.
The size pair uses the same otherwise-valid selected kind/version/request JSON,
padded only with trailing ASCII spaces to exactly 4,096 and 4,097 bytes. The
first must be accepted and the second must fail intake. Both retain actual file
size and SHA-256, so malformed JSON cannot satisfy the size rejection.
Publication cases separately qualify the writer. Their literal JSON values serialize
to exactly 4,096 and 4,097 bytes including the final newline; the frozen sizes and
SHA-256 values are independent expected bytes. Rejection at the upper boundary
must create neither a final nor a pending file. Owned bad-mode and symlink-alias
directories must reject publication, with the original directory mode restored.
An existing pending or final file must remain byte-for-byte intact. A final-name
collision retains the newly written pending candidate as failure evidence. An
unrelated I/O failure cannot satisfy an expected collision. These cases operate
only within a separate owned qualifier directory and do not restart a daemon.

Positive intake does not establish the complete acknowledgement or adoption
join. Those fields, actual daemon stop/start, successor identity and persistence
remain required in the existing real restart scenario. Every passing rejection
must retain its intended error and physical witness; unrelated errors and late
completion cannot satisfy another rejection. These pure file cases do not
qualify an actual daemon failure, recovery, human, user or production result.

Independent expected, source/public and distinct package admission precede
consumption. All reusable preparation, lifecycle and observation code remains
measured. The assertion driver and registries must preserve every existing case.

The additional actual relay cases retain all prior expectations. A complete Z
header with declared length 3 and a complete malformed C tag must return
InvalidData before forwarding. A complete header without its four promised body
bytes must hit the existing 2 s read limit while the producer waits 2.3 s;
TimedOut and WouldBlock are the admitted native timeout spellings. Each producer
must complete and no bytes may reach the drainer. A separately closed actual
forwarding target receives a complete five-byte frame from the producer and must
produce BrokenPipe in the server path, with actual read shutdown and peer closure
before the server call. These cases do not qualify a daemon or change limits.

Additional helper qualification keeps every previous case and failure guard.
The allocator uses an injected local atomic counter in its unchanged measured
implementation so one actual occupied directory, complete 32-attempt exhaustion
and non-root permission denial can be prepared without racing the live counter.
All physical prefixes remain under a freshly owned private temporary parent;
existing markers survive attempts, and only created owned entries are removed.

The selected service directory is temporarily 0770 for each guard call and always
restored to 0700 before interpreting results. Exact output/control/input/native
absence and existing-file conservation are asserted independently. Invalid live
and control fixture descriptors must reject their intended defect before native
effects; missing collision bytes are validated before creating the pending file.

Snapshot boundaries use 33 exact listed synthetic inputs, independent actual
COUNT/key observations and committed temporary owned setup. Exact32 succeeds and
33 rejects. The exact PostgreSQL17 migration DDL establishes five live columns and six
constraints, for eleven definitions. Independent catalog queries must confirm
these counts before use. Adding 21 nullable text columns reaches exactly 32
definitions and succeeds; adding 22 reaches exactly 33 and rejects. Both lanes
independently observe all actual added names and definitions before the bounded
helper. Restoration is checked independently of that helper. Query errors use registered owned
column renames and actual SQLSTATE42703. Every setup restores baseline rows,
annotations, history and schema even if the tested outcome is wrong. No protected
ledger access is granted to the writer and no other database is changed.

Outage observations occur only after the existing acknowledged STOPPED phase and
actual old-process/socket/PID-file absence. The unchanged service collects real
results while the server is absent, inside a separate two-second aggregate budget
intersected with the original 25-second handoff. Each connection keeps its one-
second limit; start keeps the existing min(remaining,10 seconds). There is no
reset/drop probe or expensive input rehash in this window. Annotation uses the
established row and unchanged current annotation. Actual results are returned to
the assertion driver; unrelated errors are not accepted as intended outages.
These tests do not qualify recovery, production or user storage.
