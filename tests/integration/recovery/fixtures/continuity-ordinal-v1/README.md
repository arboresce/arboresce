# Continuity ordinal and family fixture profile

These original public synthetic literals are licensed MIT OR Apache-2.0. They
contain no personal records, operational credentials or real storage selection.
Independent semantic acceptance and committed delivery precede consumer use.
Ordinary checks consume frozen bytes and never regenerate expectations.

The owning requirements are [lifecycle continuity](../../../../../docs/requirements/lifecycle-contract.md#11-retention-recognition-and-independent-continuity),
[common values](../../../../../docs/requirements/common-contract.md),
[recovery](../../../../../docs/requirements/recovery.md) and
[fixture governance](../../../../../docs/requirements/project-fixtures.md).
[sources.json](sources.json) pins the exact public context, complete case inventory,
rights, input bounds, allowed consumer and exclusions. [cases.json](cases.json)
contains complete literal inputs and observations.

## Bounded consumer

The first application consumer checks borrowed typed projections of a namespace,
predecessor, checkpoint range and entry scopes. It also constructs checked family
names and positive ordinals. This is an internal library observation, not a wire
schema, journal decoder, authenticated checkpoint, capability or public endpoint.
No full continuity record or binding is represented by these smaller projections.

The family constructor accepts exactly `lifecycle_intent`, `lifecycle_resolution`,
`recognition_intent`, `recognition_resolution`, `scope_retirement_intent` and
`scope_retirement_resolution`. Comparisons are exact and case-sensitive; no alias,
whitespace trimming, normalization or seventh family is admitted. The ordinal
constructor accepts domain integers from 1 through 999,999,999,999,999,999
inclusive. The fixture records raw native constructor inputs and projected ordinal
observations as exact decimal strings. Input-only conversion to u64 never passes
through binary64. The normative positive revision wire value is a canonical
decimal string of at most 18 digits; complete wire decoding remains a separate
consumer obligation. Larger unsigned constructor inputs are exact negative cases.

A namespace contains checked organization and stream IDs. A checkpoint projection
contains that namespace, positive first/last ordinals and a previous checkpoint
digest or null. Each entry projection contains its checked organization, positive
ordinal and one of the six checked families. The explicitly supplied predecessor
is either `beginning`, or `after` with a namespace, last ordinal and checkpoint
digest. Supplied predecessor values are test context, not authentication evidence.

The scope observation requires 1 through 256 entries, an exact expected namespace,
an increasing inclusive range whose length equals the entry count, and every
entry's organization and exact contiguous ordinal. A beginning has first ordinal
1 and null previous digest. An `after` predecessor has the exact expected namespace;
its last ordinal must permit a successor, the new first is exactly last plus one,
and the previous digest equals its checkpoint digest. Maximum-ordinal exhaustion
never wraps or invents a new beginning. Repeated families are permitted; actual
record identities, payloads and associations belong to later complete validation.

The finite internal failures are `EmptyBatch`, `BatchTooLarge`, `InvalidRange`,
`CheckpointScopeMismatch`, `PredecessorScopeMismatch`, `PredecessorLinkMismatch`,
`OrdinalExhausted`, `EntryScopeMismatch` and `OrdinalMismatch`. Cases isolate their
intended invalid condition; this fixture selects no HTTP failure or public
first-failure ordering contract. A match returns only the exact first, last and
count. Every result observes the complete unchanged typed input projections.

## Oracle isolation and limits

Only a case's `input` reaches the consumer or maintained observation helper.
Expected objects, case IDs, source pins, rights and explanatory metadata stay in
thin assertions. Helpers serialize actual typed values after the call; copying
an expected object into a reported observation cannot establish an after-state.
All introduced decoding, projection, observation and process support is maintained
measured source at its own consumer, regardless of its test directory.

The package does not check actual encoded journal bytes or their 1 MiB limit,
cryptographic hashes/signatures/trust, complete binding/abort/inventory records,
durable acknowledgement, actual cutoff/tail completeness, canonical transaction
effects, replay recognition, retirement, recovery or serving permission. Those
remain mandatory before their actual consumers. In particular, a supplied null
predecessor or matching digest cannot prove an authenticated beginning or tail.

Static literals qualify no executable. Actual source requires complete fresh
owning and public-only standalone Rust 1.99.0 qualification, every required strict
source/helper/process/native scope, independent reviews and distinct delivery.
Whole lifecycle continuity and every real-input, recovery, authentication, human,
live-model, other-native, user and production gate remain unaccepted by this
package. Product and bootstrap writers remain disabled.
