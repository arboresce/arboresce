# Native collector protocol literals

These independent literals precede the maintained collector consumer. They qualify parsing and rejection logic, not actual Cargo, LLVM, source freshness, process conservation or whole verification. Actual native integration and full owning/standalone qualification remain mandatory. The owning testing contract retains every existing threshold and adds actual binary-owned module scopes.

Each case has one literal ID, action, raw input and exact value or fixed error text. All raw inputs are frozen JSON strings; no consumer generates expected outcomes. Each must execute once and report its ID. Reusable input preparation is measured source. A malformed fixture/preparation failure is not a consumer rejection.

Environment action consumes default cargo-llvm-cov0.9.1 show-env assignments, a selected external target, exact wrapper spelling and complete expected workspace crate-name set. Require the nine exact supported keys, valid values, exact target/profile pattern using the explicit actual workspace basename, selected wrapper spelling, fixed instrumentation flags and equal crate-name sets. Repeated known crate-name tokens preserve the actual tool's alias behavior. Quoted strings and safe unquoted tokens are parsed without shell evaluation. Support shell single-quote apostrophe escaping, preserve raw unit separators and reject unknown keys, duplicate keys, malformed/unclosed quoting, shell substitutions outside quotes, command syntax, missing keys, changed values or a truncated final line. Export-prefix syntax is outside the selected default output profile.

Dependencies action selects actual Rust1.99 Cargo compilation dependency rules for one exact known object. The real producer leaves object targets unescaped, including spaces, colons, hash, dollar and apostrophe characters; it escapes spaces in dependency names but retains other observed punctuation. Match the exact known raw target followed by its rule colon; also accept the explicitly escaped target form in the retained literal. Do not infer a target by splitting on its first space or colon. Return the complete unique selected dependency set, decoding escaped space/colon/hash/backslash and backslash-newline continuations. Unescaped colons and hashes inside dependency paths are ordinary characters, not extra rules or comments. Ignore blank/whole comment/env-dep lines and nonselected output/phony rules. Reject duplicate selected rules/dependencies, missing or empty selected rule, malformed escaping or truncated final line. Caller must reopen every selected path and compare all compiled Rust source with the reviewed closure; this parser does not attest file identity. The prior unescaped-colon rejection was a mistaken hand-authored assumption, corrected using actual compiler output before any source checkpoint acceptance.

List action parses the actual --list --format=terse stdout. Every nonempty line is a unique nonempty whitespace-free name followed by ': test' and LF. Empty stdout represents a genuinely incidental empty harness; the required-suite caller must reject empty selection. Benchmarks, summaries, duplicate names and truncated or malformed lines fail. Registry equality is a separate consuming check.

Execution action consumes --show-output --test-threads=1 pretty-format stdout, exact test metadata and actual harness PID. Freeze the running header, one ordered result for each selected test, two successes headings, optional captured stdout sections, sorted unique success-name list and one terminal all-passed zero-failed/ignored/measured/filtered summary with finite decimal-second duration and final LF. This profile retains raw child diagnostics interrupting a pending result line; only the actual subsequent 'ok' finishes that test. A diagnostic cannot supply another test header, summary or event. Blank formatting lines are retained. Explicit zero-test transcripts are valid only for a separately nonrequired incidental harness.

Test metadata has name, prefix and case_ids. Names are unique; a null prefix requires no case IDs. Recognized prefixes are 'xtask case=', 'identifier case=' and 'collector case='. Events are complete standalone '<prefix><id> pid=<actual harness PID>' lines only inside that successful test's captured stdout section. Each expected case occurs once in its own section; unknown, missing or duplicate events fail. JSON strings or nested diagnostic payloads containing a prefix are not events. Return the exact test-to-sorted-case-ID map. Malformed/duplicate test metadata fails as invalid input, distinct from an invalid execution transcript.

Actual Rust1.99 source and complete real probes establish this selected libtest format, including diagnostic interleaving and empty-body tests. They do not supply new expected rejection outcomes. Profile/native/process/input gates are added with their own independently reviewed literals before consumption. These protocol cases alone cannot close the maintained collector or whole checkpoint.

The profile stem is the actual workspace directory basename, not a fixed product name. Existing cases explicitly select arboresce. The source-basename positive and mismatched-basename negative qualify this independent context. The collector invokes the exact prepared cargo-llvm-cov program directly for show-env; Cargo subcommand discovery cannot replace it with another installed plugin.

The expected wrapper crate-name set is the union of every actual workspace member package name, that package name with _tests appended for the selected plugin's try-build alias, and all its target names, with hyphens replaced by underscores. Repeated names are allowed in raw output but the complete set must match. External packages do not enter this workspace-member set. The real mini selected-plugin command, wrapper path and target/build paths must match together; earlier routed diagnostics do not establish that combination.
