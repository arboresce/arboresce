# Architecture and dispatch literals

This public synthetic package contains 29 dependency, 53 Rust-source and 13
command cases, plus one separately inventoried non-UTF-8 intake case. Expected
values are independently authored from the engine
[architecture](../../../../docs/requirements/architecture.md),
[dependency baseline](../../../../docs/requirements/dependency-qualification.md)
and [testing contract](../../../../docs/requirements/testing-and-coverage.md).
All material is original synthetic data under MIT OR Apache-2.0. There are no
customer inputs, credentials, private paths or live-model results.

The current production domain is standard-library-only. The explicit application
and workflow examples permit inward values and the selected deterministic SDK
and reject concrete infrastructure, Core internals and unselected profiles.
Controlled dev dependencies confer no production import authority. Future pure
dependency/role/API profiles are amended and independently qualified at their
first consumers; this profile does not permanently prohibit qualified pure
libraries or prove actual SDK compatibility.

Rust snippets are syntax/policy inputs, not executable mock workflows. SDK type
names belong to its selected 1.0.0 public interface. Configured import/path
guards complement code review; they do not prove arbitrary Rust data flow or
effects hidden by unqualified macros. Strings remain data. Explicit negatives
cover ambient clocks/I/O, unsupported SDK surfaces, panic/unwrap/unsafe, aliases
and wildcard bypasses.

Independent expected acceptance precedes consumption. Never derive expected
answers from the guard. Retain every case ID and run actual workspace commands
separately: vector tests cannot prove child execution. Native exit/output/profile
evidence remains required. The first increment exposes architecture, format,
check, test, Clippy and help. Coverage/whole verify remain unavailable until
their second accepted increment. Whole E202 and maintained source/native/runner,
service and Temporal-runtime qualification are separate required gates.

Display errors contain no line ending. Emitted guard errors add exactly the
fixed tool prefix and one LF on stderr. Help and accepted architecture output
use stdout; usage/spawn failures use stderr. Failed child streams/exits pass
through unchanged, with no parent success frame. Metadata stdout is consumed
by the guard, and actual Cargo stderr diagnostics remain distinct. Owned output
write/flush failure exits1. The output_profile freezes these stream distinctions.
