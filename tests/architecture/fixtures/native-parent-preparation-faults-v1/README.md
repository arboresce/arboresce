# Native parent preparation faults

These independent literal expectations precede their test consumers. They
qualify the existing measured capture helper's handling of parent preparation
failures after a real built peer has exited normally. The peer runs its existing
pass mode, with its fixed stdout and stderr; expected objects never enter the
peer command or determine its result.

The three controls cover a parent callback error; a missing owned acknowledgement
after actual child exit; and a conflicting regular local exit-receipt file.
The final control preserves the primary setup cause in the trace while the
local completion returns AlreadyExists. The actual ambient completion must
still succeed. Keep genuine local launch/context bytes unchanged and retain the
conflicting file separately from valid native evidence.

Retain the actual child status, parent error kind, setup error kind, both
completion outcomes, source context, native trace and exact streams. The
original 3000 ms observer, 2000 ms handshake and 2000 ms cleanup limits remain.
These cases exercise post-exit failure handling. Existing requirements for
live-child termination, escalation, profile conservation and real recovery
remain separate and unchanged.

All 37 original launch-publication cases, every other literal and all strict
coverage scopes remain unchanged. A successful focused run does not close the
failed full collection or any whole checkpoint. Fresh complete owning and
public-only qualification remains required.
