# Collector component boundaries

These independently reviewed literals cover the shared decoder for actual selected-tool version output, physical output/object/receipt/dependency intake, profile names, real Cargo configuration discovery, bounded JSON, preparation errors, native probe failures, real command cleanup and isolated module-layout rejection. The physical executable fixtures are component inputs and are never launched or described as native artifacts. Literal version output never qualifies an installed tool. The existing real mini collectors still execute the selected Rust and LLVM tools and qualify actual instrumentation separately.

Every prior case and required scope is retained. Preparation failures remain distinct from consumer rejection. Sized read recipes accept 1 through 67,108,864 bytes; hexadecimal recipes require complete valid pairs. Shared version decoding preserves production interpretation. The Runner cases reuse a successful real mini's selected tool manifest; they launch actual sleep/false, and reject a changed selected hash before launch. The sleep deadline requires bounded termination, a retained completion error, actual reaping, and the exact launch/exit receipt pair. The configuration case operates only on owned files and compares unrelated ancestor records unchanged.

The module cases preserve complete literal byte strings. Command-count rejects 40 commands in a312-byte table; zero commands leave that table unconsumed. VM start overflow and a section's wrong segment name are isolated. The counter section is23bytes while its containing segment remains valid. The raw header declares four counters, inserting an eight-byte zero counter immediately before names while both data records still own only three counters. These supplied malformed layouts do not qualify actual native instrumentation.

Object recipes fix the exact UTF-8 payload `object\n`, Unix executable/nonexecutable modes, and the owned symlink target. `$object` denotes only the task-owned physical input path. Dependency recipes likewise freeze the selected image name/bytes/mode/hash, each physical candidate and dependency payload, and total directory entries. Exactly4,096 entries must succeed with one matching image plus its dependency file and4,094 unrelated entries;4,097 must reject with the same otherwise-valid matching pair plus4,095 unrelated entries. No real executable or retained qualification artifact is mutated. The invalid resource-count recipe is otherwise complete, so omitting its preparation bound cannot preserve the expected rejection.

Supplied dependency/report projections exercise production-used source-set and report-count decoding, including an in-root non-source dependency, physical missing/outside/unregistered sources, malformed report files, and duplicates. They never qualify native coverage. Preflight inputs intentionally stop before tool preparation or command launch; placeholder sysroot/plugin files are never used as installed tools. Reused real-mini cases reopen the actual selected tools, compare the real selected rustc sysroot, reobserve real resources against changed declared hashes, and reject malformed roles after actual Cargo metadata. Their original successful source and evidence remain immutable; every failing invocation has separate retained output, actual status and stage-specific command inventory.

These failures do not fabricate receipt pairs or modify global environment.

Preservation checks bind every pre-existing baseline source/evidence file byte. New actual outer-context launch, exit and profile records may be added outside an inner case-output directory, as required by capture; retain and reconcile their actual PID/hash/status/profile joins separately. They are permitted additions and never overwritten baseline files or ignored processes. A successful ambient completion API can be a no-op during an ordinary unmeasured narrow invocation; a full measured run must retain its actual active ambient receipt.

On a setup error, cleanup timing starts before local launch recording and ends after the owned child is confirmed reaped. This conservatively includes the actual termination performed inside a failed recording operation as well as the subsequent status check. Receipt-completion attempts are retained separately. A cached post-termination status check alone cannot establish the termination bound.
