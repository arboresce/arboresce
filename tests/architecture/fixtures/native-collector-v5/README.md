# Selected runtime, module and finalization expectations

These independent literals precede repair of the collector integration. The selected format is Rust1.99.0/LLVM23.1.1 Front-end rawv11 and little-endian ARM64 MachO executable. They do not introduce another platform or replace actual owning/standalone qualification.

The runtime check consumes actual selected rustc --print sysroot stdout. Require one exact canonical declared path followed by LF. The seven Rust/Cargo executable program and canonical-image locations are that sysroot/bin/name; the two LLVM tools are its lib/rustlib/aarch64-apple-darwin/bin/name. The selected plugin and operating-system utilities keep their separately prepared identities. An unrelated resource tree cannot qualify the compiler actually used. Native reuse checks the real selected compiler response against a different task-owned physical sysroot.

The module gate consumes complete bounded regular-file bytes of each selected actual object and actual raw profile. MachO magic, CPU, execute type, complete bounded load-command table and section ranges must validate. Exactly one data/counter/names section is required; duplicate/missing/truncated/overflowing sections fail. Empty incidental instrumentation data and counters are allowed, with their actual names section still matched. Unsupported live bitmap/uniform/vtable/value-site instrumentation fails in this default profile.

LLVM rawv11 uses the fixed19-u64 header and72-byte data records. Validate the selected magic/version, no variant bits or binary IDs, complete bounded section sizes, zero unsupported instrumentation, exact counter-section size and complete terminal names/padding with no second module or trailing bytes. Match the actual raw and static complete instrumentation records by NameRef, CFG hash, counter layout and the remaining static value-site/bitmap fields, excluding runtime pointers. Match complete encoded names bytes and counter cardinality. Counter values may differ, including zero and positive profiles; they do not alter identity. The actual LLVM show parser separately validates names/counts/structure/activity. This static gate adds content identity; it does not claim a Darwin embedded binary ID, cryptographic process attestation or support for another raw version.

The native module case reuses all12actual completed mini profiles and six objects from the existing positive native case, checks every physical original pair, and then checks a task-owned copy with another actual object's positive raw bytes. Exact original evidence hashes remain unchanged. No additional collector run or synthetic native result is substituted. The names comparison retains valid empty incidental profiles.

Bounded read cases freeze regular UTF-8 text at an inclusive4-byte limit, oversize, FIFO, symlink, directory and expired-deadline rejection before consumption. The same bounded regular intake is used for actual .d files and external JSON manifests. Freshness cases reopen a real task-owned object after its recorded hash, then test unchanged bytes, append, replace, remove and expiry. Every changed/unreadable object fails as collector inputs changed. Actual selected compiled object paths are reopened and compared again during finalization.

Input, profile/binary collection and finalization phases each keep one enclosing180-second deadline. All nested intake/hash/parse/receipt/metadata/output work shares its phase deadline; command-specific budgets remain additional upper bounds. An expired phase cannot emit a successful result. Existing per-command budgets,8MiB streams,2-second cleanup,920 prior expected tool outcomes and all original strict scopes remain unchanged except for the separately reviewed additive workspace-basename context.

Counter pointers are normalized to each actual counter section: raw record index*72 plus signed CounterPtr minus header CountersDelta, and object record address plus signed CounterPtr minus static counter-section address. Each range is8-byte aligned, positive, contained, disjoint and collectively complete. Normalized per-record ranges must match. Runtime addresses (NamesDelta and unused BitmapDelta) are not executable digests. Unsupported default record pointer/value-site/wave/bitmap fields fail rather than being ignored. Names padding is zero to the next8-byte boundary. Ambiguous compatible objects fail; metadata compatibility alone never establishes a unique executable identity.

Two further real mini variants substitute a completed actual positive or zero-data raw file during the final actual required test, before first collector intake. Original/replacement bytes and the still-present expected PID path are preserved outside source/raw/context. The zero-data variant must use another actual module with different names. Valid LLVM inputs, fresh mtime, filenames, source, receipts and tools remain otherwise intact. Both fail for process/profile identity. The post-success physical module case remains a12-pair positive and unchanged-evidence check. A plugin-conflict assertion reuses actual positive receipts and hashes; it cannot relabel the routed diagnostic.

The dependency exact-limit input is an otherwise-valid rule padded with spaces to8MiB including its LF;8MiB+1 is rejected by physical intake. A symlink in any ancestor also fails bounded read. Same-size object mutation is separately rejected. The actual shared-deadline probe uses the real prepared true command with its ordinary30-second budget, waits until the single250ms enclosing phase deadline expires, then proves the next command cannot spawn. The final-output probe writes a complete real frame, waits until the shared deadline in flush, and returns a successful flush; the collector still returns1 and invalidates that frame.

The synthetic MachO segment's actual file extent equals the complete object bytes. The isolated segment+1 negative changes only that declared bound. A valid nonzero raw CountersDelta=-1920 with CounterPtr=-1920/-1976 retains normalized ranges[0,16)/[16,24); raw NamesDelta and unused BitmapDelta are allowed to be nonzero. Changing only that delta to0 fails.

Substitution candidates must have actual completed B receipt PIDs, exclude the current harness, satisfy minimum/maximum bytes, magic/version/unsupported-feature and full checked layout bounds before any record/name indexing. The parent independently reconciles target/replacement paths to the actual different selected object launch identities. No distinct eligible pair is a fixture preparation failure.
