# Native collection conservation literals

These literals define pure validation of observed collection facts before its consumer implementation. They do not substitute for actual filesystem intake, LLVM parsing, native integration, source coverage or whole collector acceptance. The real collector must produce these facts from the complete actual inputs, receipts, artifacts, raw profiles and LLVM outputs. Fake facts are unit inputs, never real qualification evidence.

The exact base is native-collection-facts-v1. It binds one immutable context (run/source/context digests, canonical context bytes, actual driver PID and inclusive observation timestamps), complete before/after input categories, typed owned objects, actual harness list/run command identities, immutable launch/exit wrappers, inspected raw profiles, the final raw filename/hash/size set and each native binary's owned-source region scope. SHA values are lowercase64hex and run IDs32hex; all actual PIDs and counts are positive where required. Wrappers retain the actual raw-byte digest separately from the parsed record. A unit wrapper digest is a supplied observed fact; this validator alone never establishes that bytes were physically read.

Object paths and digests, launch PIDs, completion PIDs and profile names/PIDs are unique. Owned object roles are binary or harness. Each harness has exactly one explicit list and run command with matching object/PID and exact launch argument bytes. List uses `--list --format=terse`; run uses `--show-output --test-threads=1 --color=never`. Owned executable path bytes and digest must both match the selected object; a required harness has positive test_count and actual run exit0/positive counters. Incidental empty harnesses have zero tests, valid profiles and actual zero exit, but do not count as required successes. The base retains two independently required harnesses so converting one to incidental never manufactures an empty required selection. Aggregate required test collection remains positive.

Every owned Rust launch has one profile and real completion under the same context/source/parent/executable identity; every profile names its exact launch PID and object digest. Native children may have expected real nonzero exits or signals, which their owning assertions must qualify. External prepared tools have launch/exit/tool identity but no project Rust profile. Parents are the actual collector driver or another observed owned Rust process. Every parent chain must be acyclic and reach the actual driver; self-parent, phantom-parent and isolated owned cycles fail. Ordinary native objects and required harness runs need positive counters; list/incidental profiles retain valid zero activity. Profile size is nonzero, counters coherent and mtime inside the run. Filenames are run-directory-local arboresce-<PID>-<module-signature>.profraw with exactly the observed PID. Compare the complete final raw set/digests/sizes and raw bytes after processing; duplicate, lost, empty, stale, future, changed, mixed-context, unknown and incomplete evidence fails.

Launch and exit wrappers use their actual versioned measurement records. Completion binds the matching raw launch digest; context, PID and parent match. Exit is exactly one real unsigned Unix exit code0..255 or positive signal. A repeated observation is one invocation, not a duplicate launch/profile. An unknown executable hash cannot be reclassified as an external tool by omission.

Native scopes preserve all prior global/file/package/library/typed-target gates. Each ordinary binary additionally has exactly one independently nonzero strict region scope using that exact object's PID profiles. Actual Cargo compilation source closure equals the reviewed registered closure and object-owned closure, including every module/generated source; count keys match it exactly. Raw count/covered/notcovered are coherent unsigned 64-bit integers; use checked aggregate totals and wider exact10*covered>9*total. The complete multi-module positive, near-u64 threshold pair and coherent aggregate-overflow negative freeze these arithmetic requirements. Wrong object/profile/source sets, zero, exactly90percent, malformed counts and unknown closure fail. Shared library qualification remains complete and separate.

All source, external manifests, tool, resource, Cargo config and native-feature before/after categories must match exactly, including additions/removals/renames. Their mismatch is 'collector inputs changed'. A wrong facts version is 'invalid collector input'. Process/profile/source-scope or structural fact mismatches are 'collector process/profile mismatch'. Positive output freezes exact object/profile/native/harness/required/external/receipt counts. Every case applies its independently authored JSON-pointer replacement input recipe to the fixed base and asserts the literal result once. Preparation errors are distinct failures; reusable replacement support remains measured.

Actual regular-file boundaries, raw-byte digests and LLVM decoding still need their own meaningful adversarial intake tests and real complete owning/standalone/native/self execution. This package cannot attest those facts or close the whole checkpoint.
