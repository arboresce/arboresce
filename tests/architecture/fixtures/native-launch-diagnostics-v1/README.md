# Native launch diagnostics: original literal inputs

These original synthetic fixtures qualify bounded native failure observation.
Tyson Lupul authored this material under MIT OR Apache-2.0. They contain no
external corpus, operational credentials or customer data.

The owning [verification requirement](../../../../docs/requirements/testing-and-coverage.md#retained-native-launch-failure-diagnostics)
and original [measurement inputs](../native-measurement-v1/README.md) remain
authoritative. This package introduces literal data, not a maintained generator or
consumer. Source and runtime qualification are separate from static admission.

The current profile is the actual non-root Unix/macOS user. Read all 32 cases in
the bounded 64 KiB package; at most 32 cases and depth 10 are admitted. Preserve
every original receipt case. The runtime producer receives only each input.
Expected errors, receipt counts and outcomes remain outside the producer.

Open and preparation recipes remove or replace only owned context data, select
a missing cwd or executable, pass a still-bare program, or create an owned
nonexecutable file. Preparation happens before any child. For prepared spawn,
unlink the owned selected-program symlink after preparation while retaining the
same Command, or pass the literal NUL argument. Observe the actual spawn error;
do not guess a PID for an unreturned Child.

Record recipes prepare one immutable request and spawn the exact owned sleep
child. An ambient outer measurement, if selected, retains its own actual launch
and completion independently. Confirm the child is running before changing only
the selected context, installing an exact-PID record collision, or restricting
its owned launch directory. Actual bounded terminate/reap supplies status; the
fixture never supplies it. Restore owned permissions after observing failure.
A collision preserves the existing file, or both symlink and target, exactly.
No selected-context completion is synthesized. PIDs are checked against the
actual Child and command, not an anticipated allocation.

Retention recipes start from a genuine missing-context preparation failure,
retain the actual command-intent bytes and selected request identity, and
exercise a fresh artifact, existing file/symlink, or unwritable owned parent.
Open the owned trace before restricting that parent. Compare every primary
field, exact command/context/source digests and byte-array paths. Existing
evidence cannot be overwritten; trace fallback preserves the primary and the
actual secondary retention error. A retention result does not turn the failed
launch into success.

The four writer-unit cases deliberately control only the writer boundary.
A zero-length write makes write_all return WriteZero; a flush error returns
BrokenPipe. Their claims do not extend to an OS/hardware failure or process
status. When trace writing fails after artifact retention, the artifact still
preserves the original failure and the actual writer error propagates.

The success case requires the actual selected command, one exact immutable
launch and matching real completion. It does not qualify complete collection,
coverage, resources or a product capability. This package cannot establish the
cause of a historical unobserved failure or permit a green flaky rerun to replace
its evidence.


The second static revision preserves all original 24 IDs and adds six discriminating
oracles. The full and compact fallback templates in protocol are complete frozen
objects. Enforce their exact version, scope, keysets, types and nullability.
Replace only declared dynamic tokens in assertion bodies using independently
arranged command-intent bytes/digest, original context bytes/digest, canonical
paths and actual held Child/parent identities. Compare complete object equality;
an extra or missing field fails. Do not derive expected bindings from the
failure object's own report or a producer-selected subset.

All full envelopes have a null retention_error. On size or exclusive artifact
create/write/flush failure, trace uses the complete frozen compact fallback.
Its digests cover exact original diagnostic bytes including LF and each original
raw path byte vector. It preserves every primary/cleanup cause and actual
identity or null, while independently recording the secondary retention error.
Existing and partial artifacts are retained. Trace write/flush failure propagates;
a successfully retained artifact still binds the original primary.

Two controlled record-writer cases use the production phase/error mapping and
actual bounded cleanup of a held running child. They discriminate record_write
from record_flush, preserve the original Write error and require real signal9
reap. They qualify controlled writer behavior and actual cleanup, not an OS
file-write or flush fault. Neither creates a successful selected receipt.

Two separate error-composition units preserve a primary AlreadyExists17 alongside
cleanup PermissionDenied13, and primary InvalidData/null alongside cleanup
TimedOut/null. Their complete observation also checks the legacy cleanup-error
return convention and null Child status. They are representation/control units,
not evidence that a real child was denied cleanup or timed out.

The exact-limit and one-over cases operate solely on the frozen representation
unit packet. The literal padding counts determine every byte; the fixed full
payload SHA256 and inclusive length are independent expectations. Object keys
sort lexicographically, JSON is compact UTF-8, and exactly one final LF counts
toward 65,536 bytes. The exact limit writes the complete artifact and trace.
One byte over returns size/InvalidData before artifact creation and writes the
literal compact fallback with exact original length/digest and preserved causes.
Synthetic reported paths and PID4242 in these units are never native evidence.

The third static revision preserves all 30 prior inputs and operations and adds
two controlled artifact-retainer cases. Both begin with a genuine missing-context
preparation error and the same production retention mapping. Perform real
exclusive creation of the owned artifact before wrapping its writer. The write
case writes exactly the frozen 11-byte prefix and then returns zero, producing
WriteZero; retain that partial file exactly. The flush case writes the full
envelope bytes and returns BrokenPipe at flush; retain those bytes without
claiming successful flush. Both require the complete compact trace fallback,
original primary/cleanup/identity and all path/full-payload digest bindings, exact
secondary write or flush cause and returned stage. Scope remains a controlled
writer boundary; no OS/hardware artifact failure is claimed.
