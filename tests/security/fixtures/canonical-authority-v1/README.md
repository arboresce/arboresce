# Canonical authority evaluation fixtures

These original public synthetic literals are under MIT OR Apache-2.0. They
contain no personal records, credentials or verified signed events. They extend
the 72 unchanged current_authority cases in the independently reviewed
[authority package](../authority-v1/README.md). They introduce no maintained
generator or oracle function. Ordinary checks read frozen committed literals.

[profile.json](profile.json) selects a bounded server-internal policy evaluator.
It is a processing profile under the existing public security, storage, resource
and fixture requirements. It changes none of those requirements. [cases.json](cases.json)
pins exact owning inputs, all original identities and complete additional inputs
with separately authored expected observations. Read limits apply before JSON
decoding. No expected object enters the production evaluator.

The explicit trusted configuration chooses supported policy and source IDs.
The fixture policy is injected only by the test. Renamed-policy positives reject
a production implementation that hardcodes that fixture name. Canonical row
observations supply current revisions and restrictions; cached hints, aliases,
names and asserted authorizers confer no authority. An asserted authorizer is
rejected. This is not a new HTTP body, authentication API or deployed policy.

The evaluator checks current direct membership or every immutable selected grant
link, restrictive source intersections and exact supplied target control.
Its result records the actual executor, complete selected scope, action, purpose,
chain or null, current executor membership and revisions. A result is a pure
observation, never a transferable permission or final-effect token. The five
final-snapshot cases require evaluation of the new snapshot; they do not qualify
a conflicting database lock or a concurrent effect.

The nine originally admitted decisions also have complete frozen typed observation
objects, including both workspaces and fresh revision/epoch values.

The structured record model is borrowed by the evaluator. Input vectors and
strings already exist before evaluation; the adapter remains responsible for
bounded byte decoding, allocation, canonical SQL lookup and transaction work.
The evaluator checks every relation/nested collection/string bound before
semantic traversal and allocates no heap. A snapshot is a bounded projection,
complete for every selected/participating required record. It is not a global
database export; unrelated well-formed rows do not cause foreign reference or
unsupported-policy resolution. Missing required records still deny. Current canonical reads, conflicting
permission-writer locks, actual races, bootstrap, shared admission and pooling
remain mandatory at their separate consumers. Existing readonly tenant roles
and sessions retain their boundary. All product/bootstrap writers stay disabled
until authentic independent lifecycle continuity and their own gates pass.

The 16-entry action-set capacity is defensive. The currently supported requested
actions are only project.read and project.change.review. Unused unsupported
grant/root action names in a direct-read snapshot cannot grant any action;
selected grant actions must all fit current root authority. No financial action,
human assurance, live provider, recovery, native release, user or production
qualification is inferred. These cases require actual maintained-source/helper,
complete fresh owning and public-only standalone qualification and independent
review before acceptance.
