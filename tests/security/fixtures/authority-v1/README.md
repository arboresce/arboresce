# Independent authority fixtures

These original public synthetic literals are under MIT OR Apache-2.0. They
contain no customer records, private originals, secrets or operational credentials.
They define independent semantic expectations before the current-authority
implementation. They are data, not a second normative specification or a runtime.

The owning public requirements are [identity](../../../../docs/requirements/identity-contract.md),
[security](../../../../docs/requirements/security-and-privacy.md),
[API admission](../../../../docs/requirements/api.md),
[relational enforcement](../../../../docs/requirements/storage-and-search.md),
[shared resources](../../../../docs/requirements/resource-profiles.md), and
[fixture governance](../../../../docs/requirements/project-fixtures.md).
[sources.json](sources.json) pins complete consumed public inputs, rights, exact
case bytes, required case identities, bounded reads and consumer scope.

`source_revision` records the original public requirement baseline. Exact `sources`
hashes select the currently admitted bytes; explicit `source_amendments` retain
the checked predecessor and old/new hashes for later reviewed corrections.
The principal-index amendment reconciles a stale issuer/subject index row with
the already selected profile/version/public-key identity. It changes no case,
profile, right, read bound, consumer group or expected result. A new consumer
must independently admit the amended exact pins before reuse; historical runs
remain bound to their original inputs.

[cases.json](cases.json) contains complete inputs and a separate `expected`
object for each uniquely named case. `selected_fixture_policy` documents only
the explicitly injected synthetic policy. It selects no production policy.
All IDs, clocks, names, keys, states, budgets, schedules and result bytes are
fixed test data. Syntactically shaped public keys are never curve/signature
verification positives. Names overlap intentionally; they never supply identity.

`current_authority` covers canonical principals, both selected workspaces,
membership and policy changes, restrictive source-policy intersections, exact
immutable own-key grant chains, target CAS and final-effect observations.
`tenant_relations` specifies nonowner/FORCE-RLS, missing context, commit/rollback
connection reuse and exact composite relationships. `bootstrap_scope` tests
operator/namespace/policy/one-use semantics while keeping every writer disabled.
`authority_races` fixes independent session/barrier order and exact linearization.
`shared_admission` fixes one shared organization/global multi-resource ledger,
reservations, ownership/fences, rollback and uncertain-effect responsibility.
No static literal qualifies actual SQL, a race, a pooler or external dispatch.

`origin_body_clock` and `event_replay_and_command_identity` are explicit
synthetic verifier-output decision inputs. They contain no allegedly verified
signed event. A future HTTP caller must never supply a verifier observation or
canonical authority flag. Exact external NIP revisions, libraries, algorithm and
fixed valid/invalid signed vectors remain mandatory before the authentication
consumer. The finite clock and reservation values select this fixture profile
only. Clock tolerance is inclusive at both thirty-second boundaries; grant and
reservation/replay expiries are exclusive. Rollback below the last healthy clock
observation keeps authentication unavailable. Untrusted forwarding headers never
select the server origin. URL/query/percent spelling and received body bytes are
exact; command canonicalization does not relax signed-body binding.
An authentication-binding positive does not admit an HTTP route or command;
the independent registered-route/body/authority gates remain mandatory.

The command preimage includes the exact zero byte after `arboresce.command.v1`,
then the complete ASCII-only canonical object. The literal hex is the declared
preimage of its SHA-256. No general JSON canonicalizer is introduced. Response
receipts retain their original command/result identity and terminal-relative
seven-day replay and thirty-one-day diagnostic/tombstone-detail retention intervals. A fresh signed attempt
does not create a new business command, and expiry never makes a known command
new. Minimal recognition persists while the organization/principal scope can
admit commands; only the independently durable irreversible scope-retirement
barrier permits its removal. The explicit post-diagnostic retry keeps minimal
recognition after original details disappear and admits no new effect. The
[lifecycle owner](../../../../docs/requirements/lifecycle-contract.md) governs
these conditions. Current disclosure authority precedes returning any original result.

Only E205's explicitly listed groups may be consumed after independent fixture
acceptance. Its actual source, helpers, PostgreSQL nonowner/RLS/lock/quota/race
profiles and complete strict coverage must qualify at that consumer. The later
semantic groups preserve their required independent oracle meanings; they do not
admit an authentication implementation. No product/bootstrap writer precedes
authentic independent lifecycle continuity. No human, live-model, native-release,
managed, user, restore or complete corpus/product gate is closed here.

Ordinary checks read these frozen regular files and never regenerate them.
There is no maintained builder, decoder, generator or oracle function in this
package. A consuming decoder/helper joins its owning measured source before use.
The runtime projection excludes every expected outcome; no model or production
resource receives the oracle package. Changed consumed inputs require exact
reconciliation and affected independent qualification before reuse.

All package-specific input and expected objects are fixture observation types.
`request` is a normalized injected policy input, never a new HTTP body. Exact
registered operation/action/purpose, request/result/receipt and problem contracts
remain authoritative before any live route. `reason` explains the independent
rule and does not mandate first-failure exception ordering. `problem_expectation`
asserts only registered code/status; `disclosure_expectation` is a separate test
assertion, never an added wire-body field. Shortened observation records do not
define a replacement public schema. No external caller provides these records.

Race effect counts name only the explicitly identified isolated admission marker
rows and their test observations. Complete canonical after-snapshots, fresh
post-revocation steps and unchanged empty product receipt/effect collections are
literal expectations. Every product/bootstrap writer remains disabled. Quota
ledgers identify both existing and new reservations with exact resource vectors,
ownership, fence and deadlines; organization totals and global totals conserve
those records exactly. A permitted renewal changes only its exact expiry and
preserves the original total deadline and ownership. New dispatch counts are
zero; no literal represents actual provider use or spending.

The post-diagnostic case stores exactly the lifecycle owner's `recognition_entry`:
recognition scope/hash, admission time and intent relation. Its incoming identity,
recognition preimage/hash and separately typed historical retention observations
are transient test inputs, never fields retained in the minimized index. No raw
key, request fingerprint, result or receipt is stored in that index. Race marker
and observation IDs are preallocated test inputs per session/command, including
unused identities for denied attempts. Expected answers supply no runtime IDs.
