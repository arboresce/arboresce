# Independent shared admission fixtures

These original public synthetic literals use MIT OR Apache-2.0. They contain
no customer records, secrets, operational credentials or external provider use.
They define independently reviewable expectations before their consumers.
They are data; no maintained generator, decoder or runtime lives here.

The owning requirements are [shared resources](../../../../docs/requirements/resource-profiles.md),
[relational enforcement](../../../../docs/requirements/storage-and-search.md),
[API admission](../../../../docs/requirements/api.md),
[security](../../../../docs/requirements/security-and-privacy.md) and
[fixture governance](../../../../docs/requirements/project-fixtures.md).
The original [authority package](../authority-v1/README.md) retains all 23
shared-admission cases unchanged, including complete organization/global ledgers
and actual two-session last-slot schedules. This package supplements them.

`profile.json` selects exact public inputs, bounded synthetic configuration,
case identities, rights and consumer scope. `cases.json` separates complete
inputs from literal expected observations. `schema.json` declares typed storage,
ownership, constraints and finite nonowner privileges for the selected forward
schema. These declarations select no production policy, spending authority or
deployment. The earlier four migration byte sequences remain immutable.

The pure boundary cases qualify supplied typed values and explicit quota/lease
rules. Preparation failures remain preparation failures; finite error formatting
does not establish an actual database failure. Native cases require the actual
prepared PostgreSQL profile, canonical reservations, transaction-local tenant
context, forced RLS and independent committed/working state observations.
Observed backend identities, locks, actual commit/rollback and transport cleanup
must be retained. A static case never qualifies those boundaries by itself.

One canonical organization/global ledger accounts for pending and active work,
storage, memory and cost. Claims lock shared control before organization and
reservation records, reread current limits and trusted time after waits, and
commit or roll back atomically. No database lock crosses provider work. Owner
and fence checks precede control changes. Renewal preserves the original total
deadline and attempt limit. Expiry, cancellation, timeout and worker death do
not release an unresolved external effect. Unknown responsibility stays charged
and blocks another attempt until independently reconciled. Released reservation
identity remains recognized so stale work cannot recreate it.

All names, UUIDs, clocks, budgets, worker labels and schedules are injected test
inputs. Worker labels are not authentication credentials. Supplied caller and
clock observations establish no real authentication or healthy clock provider.
No HTTP caller may provide a verifier result or canonical authority flag.
There is no provider dispatch or accepted product effect in these cases.

Runtime projections receive input and independently supplied trusted
configuration only. Expected values and case identities stay in thin assertions;
they cannot determine an implementation result. Complete original ledgers and
new declared observations must be compared, rather than checking only success
or one selected field. Actual source, support, process, native and coverage
qualification remains required after independent literal acceptance.

The planned Rust input profile is independently enumerated before its consumer.
Its additive native inventory entry preserves the original 80-source and later
82-source entries. A declared future count is not an observed source inventory
or executable qualification. Consumer admission still requires exact raw-input
hash selection, complete inventory and all existing native assertions.

No authentication, general pool, product or bootstrap writer, grant consumption,
owner insertion, authentic lifecycle, human assurance, live-model, native release,
recovery, user or production acceptance follows from these literals. Their own
real consuming gates remain mandatory. Ordinary checks read committed bytes and
never regenerate expectations from the implementation.
